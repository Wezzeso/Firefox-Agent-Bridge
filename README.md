# Firefox Agent Bridge

Управляйте Firefox из Codex: страницы, кнопки, формы, вкладки, iframe и скриншоты. Одна команда устанавливает мост, подключает MCP и открывает отдельный Firefox с расширением.

[English](README.en.md) · [Как это устроено](docs/architecture.md) · [Ограничения и доступ](SECURITY.md)

## Установить одной командой

Нужны **Linux или macOS**, **Python 3.9+**, обычный **Firefox 128+** и **Codex**. Дополнительные Python-пакеты, Node.js, Docker, ключ API и `sudo` не нужны. Windows пока не поддерживается. Для Snap/Flatpak Firefox установите обычную сборку [с сайта Mozilla](https://www.mozilla.org/firefox/new/).

```sh
curl -fsSL https://raw.githubusercontent.com/Wezzeso/Firefox-Agent-Bridge/main/install.sh | sh
```

Откроется отдельный Firefox с разрешённой начальной вкладкой. Один раз обновите подключение MCP или перезапустите Codex. После этого напишите:

> Используй Firefox Agent Bridge. Покажи разрешённые вкладки и открой нужный мне сайт.

Для повторного запуска достаточно открыть **Firefox Agent / Firefox для Codex** в приложениях или выполнить:

```sh
firefox-agent
```

Если оболочка не включает `~/.local/bin` в PATH, установщик покажет полный путь команды. Ярлык в приложениях работает независимо от PATH.

<details>
<summary>Установка из исходников, без curl | sh</summary>

Скачайте ZIP этого репозитория, распакуйте его и выполните в его папке:

```sh
python3 setup.py
```

Либо клонируйте исходники:

```sh
git clone https://github.com/Wezzeso/Firefox-Agent-Bridge.git
cd firefox-agent-bridge
python3 setup.py
```

Проверить установку, не открывая окно: `python3 setup.py --no-launch`.
Указать путь к Firefox: `python3 setup.py --firefox /absolute/path/to/firefox`.
Для другого MCP-клиента: `python3 setup.py --skip-mcp`; команда STDIO-сервера — `firefox-agent mcp`.

## Команды

| Команда | Действие |
| --- | --- |
| `firefox-agent` | Открыть Firefox с расширением |
| `firefox-agent https://example.com` | Начать с нужного сайта |
| `firefox-agent status` | Проверить соединение |
| `firefox-agent tabs` | Показать разрешённые вкладки |
| `firefox-agent doctor` | Проверить Firefox, мост, MCP и ярлык |
| `firefox-agent stop` | Немедленно отозвать доступ ко всем вкладкам |
| `firefox-agent update` | Обновить программу, сохранив профиль |
| `firefox-agent uninstall` | Удалить подключение, программу и ярлыки, сохранив профиль |

Остановка в Firefox: **Alt+Shift+X** или **«Остановить всё»** в расширении. После остановки доступ к вкладке включается кнопкой расширения. Повторный запуск команды не включает отозванный доступ в уже открытом браузере.

При удалении закройте окно Firefox Agent, чтобы выгрузить временное расширение. Если хотите также **безвозвратно удалить отдельный профиль**, сначала закройте его окно и выполните `firefox-agent uninstall --purge`.

## Что умеет

20 MCP-инструментов: чтение страниц и полей, снимок интерактивных элементов с ID, клики, ввод текста, select, checkbox/radio, Enter/Escape/Tab, прокрутка, ожидание, навигация, создание/закрытие вкладок, iframe, открытый Shadow DOM и скриншоты. Для агента также доступен CLI:

```sh
firefox-agent request page.snapshot '{"tabId":2}'
```

ID вкладки берите из `firefox-agent tabs`. Примеры и полный список — в [документации инструментов](docs/tools.md).

## Доступ и ограничения

Программа использует отдельный профиль. Входы в аккаунты выполняются в этом окне. При запуске доступ включается только для начальной вкладки и её потомков; другие вкладки разрешаются вручную. При переходах разрешение следует за вкладкой. При остановке, перезапуске расширения или потере моста разрешения сбрасываются.

Управление идёт через Firefox Native Messaging и локальный Unix-сокет с правами `0600`. Установочное подключение Marionette слушает только loopback и закрывается после загрузки расширения. MCP передаёт результаты подключённому клиенту Codex и его модели. Процессы того же системного пользователя могут обращаться к локальному сокету.

Расширение временное и автоматически загружается при каждом запуске через ярлык. Подпись Mozilla и отключение проверки подписей для этого сценария не нужны. Обычная постоянная установка в существующий профиль требует подписи Mozilla.

Управление использует синтетические DOM-события. CAPTCHA, WebAuthn, системные диалоги, интерфейс Firefox, файловая загрузка, закрытый Shadow DOM, canvas, drag-and-drop и аппаратные клавиши не поддерживаются. Совместимость с каждым сайтом не гарантируется. Парольные поля скрываются в текстовом snapshot; прочие тексты и скриншоты могут содержать данные страницы. Подробности: [SECURITY.md](SECURITY.md).

## Проверка и разработка

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
FIREFOX_AGENT_LIVE_TEST=1 python3 -m unittest discover -s tests -p test_live_install.py -v
python3 scripts/build.py
```

Первый запуск проверяет протокол и установщик в одноразовых домашних папках. Второй проводит настоящую установку из архива, запускает Firefox и проверяет формы, MCP-скриншот и остановку. Отдельный расширенный тест браузера: `python3 tests/test_firefox.py --geckodriver /path/to/geckodriver`. Он проверяет iframe, Shadow DOM и защиту от устаревших/перекрытых элементов.

CI проверяет установщик на Linux и macOS. Реальные браузерные проверки выполняются на Linux. При первом push и при изменении `VERSION` в `main` workflow проверяет пакет в Firefox, создаёт тег `vX.Y.Z` и публикует ZIP исходников, tar.gz, ZIP расширения и SHA256SUMS в GitHub Release. См. [CONTRIBUTING.md](CONTRIBUTING.md).
